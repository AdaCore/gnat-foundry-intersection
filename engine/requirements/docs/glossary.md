# Glossary

## Requirement Characteristics

### atomic (singular)

A requirement is "atomic" if it expresses a single stand-alone thought and
cannot be further decomposed.

### feasible

A requirement is "feasible" if it can be achieved within the technical
constraints of the project.

### implementation-free

A requirement is "implementation-free" if it states *what* is required, not
*how* the requirement is met.

### internally consistent

A requirement is "internally consistent" if it contains no contradictions
within itself.

### unambiguous

A requirement is "unambiguous" if there is a common understanding of its
meaning.

### verifiable

A requirement is "verifiable" if its fulfillment can be objectively confirmed
through a finite process of testing, analysis, or review.

## Requirement Properties

### hierarchical structure

A set of requirements has a "hierarchical structure" if it is organized into
several successive levels (e.g., "high level" and "low level").

Note: Traceability between requirement levels, as well as exceptions like
*derived* requirements, should be described in the project's development
guidance.

### completeness

A set of requirements is "complete" if the requirements at one level fully
implement all requirements of the previous level.

### external consistency

A set of requirements is "externally consistent" if they do not contradict
each other.

### no duplication

A set of requirements has "no duplication" if the content of requirements is
not repeated in any other requirement at one single level of the hierarchical
structure, and this is true at each hierarchical level.
